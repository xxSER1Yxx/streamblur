## Шаг 0. Адрес уже вписан

Ссылка `https://github.com/xxSER1Yxx/streamblur` прописана в двух местах:

1. `streamblur/__init__.py` — `__repo_url__`
2. `packaging/installer.iss` — строка 20, `#define MyAppURL`

Из неё складывается ссылка в шапке панели, адрес поддержки в свойствах
установщика и меню «Поддержка». Если репозиторий будет переименован —
править надо в обоих файлах.

## Шаг 1. Создать пустой репозиторий

<https://github.com/new>

* **Repository name:** `streamblur` — ровно так, иначе ссылки в программе перестанут работать
* **Public** (проект под AGPL-3.0 — обязан быть открытым)
* **НЕ ставьте** галочки «Add README», «Add .gitignore», «Choose a license» —

После создания адрес будет `https://github.com/xxSER1Yxx/streamblur.git`.

## Шаг 2. Отправить файлы

Откройте терминал в папке проекта и выполните по порядку:

В папке проекта есть готовый скрипт `push-to-github.sh` — он делает всё ниже
сам. Запуск:

```bash
bash push-to-github.sh
```

Скрипт спросит логин и токен и отправит файлы. Если хочется руками:

```bash
cd путь/до/streamblur

git init -b main
git add .
git commit -m "StreamBlur: блюр экрана для стримеров по таймингам + нейросеть-страховка"

git remote add origin https://github.com/xxSER1Yxx/streamblur.git
git push -u origin main
```

### Что такое токен и почему обычный пароль не подходит

С августа 2021 года GitHub **запретил** отправку кода по паролю от аккаунта —
только токен. Это ключ, который заменяет пароль и который можно отозвать, не
меняя пароль.

**Как получить (2 минуты):**

1. <https://github.com/settings/tokens>
2. **Generate new token → Generate new token (classic)**
3. Note: `streamblur push` · Expiration: 90 дней
4. Отметить **две** галочки: `repo` **и** `workflow`
5. **Generate token** → скопировать строку `ghp_...` — она показывается один раз

> Право `workflow` обязательно: в проекте есть `.github/workflows/build.yml`
> (автосборка `.exe`). Без него GitHub отклонит отправку с сообщением
> `refusing to allow a Personal Access Token to create or update workflow`.
> Это защита GitHub: токен без `workflow` не может запускать код на ваших мощностях.
>
> Токен показывается **только один раз**. Забыли скопировать — создавайте новый,
> посмотреть его задним числом нельзя: GitHub хранит лишь хеш.

**Как использовать:** когда git спросит пароль — вставить этот токен вместо
пароля. Логин остаётся `xxSER1Yxx`.

> Токен — это как пароль. Не публикуйте его в issue и не кладите в код.
> Если утёк — отзовите на той же странице и создайте новый.

Чтобы не вводить каждый раз, сохраните его один раз:

```bash
git config --global credential.helper store
```

После первого успешного push токен запишется в `~/.git-credentials` и
спрашивать больше не будет.

## Шаг 3. Проверить, что ушло

* На странице репозитория должен появиться README и лицензия **AGPL-3.0**
  (GitHub определяет её сам и напишет рядом с количеством файлов).
* Во вкладке **Actions** автоматически запустится сборка `.exe` — она займёт
  5–10 минут. Когда закончится, `.exe` и `Setup.exe` появятся в
  **Releases** (черновик релиза создаётся самим workflow).
* Убедитесь, что в репозитории **нет** файлов `.onnx` весом десятки мегабайт.
  Если есть — значит `.gitignore` не сработал, удалите их:
  `git rm --cached имя.onnx && git commit -m "убрал веса"`.

## Шаг 4. Куда пользователи будут писать

* **Баги и пожелания** → вкладка Issues. Чтобы люди понимали, что писать,
  создайте первый issue-шаблон: New issue → «Bug report».
* **Поддержать** → GitHub → Settings репозитория → раздел **Sponsorships** →
  «Set up a link» (можно указать Boosty, Donationalerts, карту — что угодно).
  Кнопка «Sponsor» появится под аватаркой, и установщик о ней уже упоминает.

```bash

```

Новая сборка в Actions запускается сама на каждый push в `main`.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `remote origin already exists` | `git remote set-url origin АДРЕС` |
| `failed to push some refs` | `git pull --rebase origin main`, потом `git push` |
| `Authentication failed` | Пароль не годится, нужен токен (см. шаг 2) |
| `refusing to allow a Personal Access Token to create or update workflow` | У токена нет права `workflow` — пересоздайте с галочками `repo` + `workflow` |
| `File … is 120 MB; this exceeds the file size limit` | В репозиторий пытаются попасть веса: `git rm --cached` их |
| Actions красные | Откройте неудачный run, смотрите шаг с ошибкой; чаще всего это отсутствующий секрет |
